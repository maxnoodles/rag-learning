# 与教学脚本的实现对照

对照日期：2026-10-15。[参考代码](https://github.com/juliepy/AI-Engineer-from-scrach/blob/main/02-RAG/03-high_level_RAG/01-graph_rag.py)为当日读取的 main 内容，未来可能变化。以下来自静态代码检查，另用同一份本地图文档对照了两个纯图检索实现；没有运行参考脚本的 DeepSeek 调用。

两者主线相同：递归切块 → LLMGraphTransformer → 内存邻接表 → 大模型选起点 → BFS。

| 方面 | 参考脚本 | 当前实现 |
| --- | --- | --- |
| 切块度量 | 120 字符、重叠 10 字符 | 60 tokens、重叠上限 10 tokens |
| 模型与 schema | DeepSeek；抽取 `strict_mode=False` | 本地 Codex；约束节点、关系类型和方向 |
| 起点选择 | 单实体名称；子串匹配兜底 | 候选号结构化输出，校验存在性，支持多实体或空结果 |
| 叶子与方向 | 无出边时取第一个父节点，再沿出边 BFS | 保留原始起点，支持入边、出边及双向 BFS |
| 子图边界 | 收集被扩展节点的全部出边 | BFS 发现节点后保留节点集合内的全部边 |
| 实体与来源 | 名称作为实体键；整段 chunk 作为关系来源 | `(type, id)`；合并事实并保留各来源和精确引文 |
| 执行与输出 | 单脚本建图、检索、生成答案 | 建图 JSON 可复用；本次做到检索报告与来源，尚未生成答案 |

## 同输入实验

读取相同的 6 个 GraphDocument，固定初始种子以排除模型选择差异：

- `Redis`、1 跳：参考实现回退到了第一个父节点“李四”，没有取回两条“项目使用 Redis”事实；当前实现从 Redis 沿入边查到知识助手项目和数据看板项目。参考结果依赖父节点插入顺序。
- `张三`、同样沿出边 2 跳：参考实现返回 9 行上下文，当前实现返回 13 条不同关系。差异来自对子图边界的定义：当前还保留边界节点到集合内其他节点的边。关系更多不自动代表检索更相关。

实验结果保存在 `artifacts/retrieval/reference_comparison.json`。参考脚本的 BFS 会收集已扩展节点的所有出边，并非只返回 BFS 搜索树；不能把它描述为一律丢掉非树边。

## 仍然共有的限制

两者均把全体实体提供给模型，并按图距离召回局部事实，尚未实现问题相关的关系筛选或检索重排；也不包含社区摘要和全局检索。当前实现多了校验与可观察输出，仍然是适合小图学习的实现。
